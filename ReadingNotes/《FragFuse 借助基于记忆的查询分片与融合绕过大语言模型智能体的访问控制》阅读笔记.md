# 《Frag Fuse: 借助基于记忆的查询分片与融合绕过大语言模型智能体的访问控制》阅读记录

原文链接：http://arxiv.org/abs/2606.15609

---

## 总览

​	Frag Fuse 利用 LLM Agent 的长期记忆机制，将一个本来会触发访问控制的恶意请求拆成多个看似正常的片段，分别写入长期记忆，之后再通过检索和融合重新组合，从而绕过 Agent 的访问控制。

​	恶意请求 → 拆碎 → 分散存储 → 后续检索 → 重新融合 → 绕过安全检查

---

## 背景知识



### LLM Agent 中的访问控制

​	对 Agent 的**用户请求、工具调用和资源访问进行权限判断**，只允许用户执行其被授权的操作。

​	**与普通 LLM 安全的区别：不仅关注有害内容，还需要结合**具体任务、工具调用、外部数据库以及用户权限进行控制。 
​	**实现方式：**通常作为独立的 **Guardrail（安全防护模块）**部署在 Agent 工作流中，并常借助 LLM 实现灵活的、上下文感知的策略判断。



### LLM Agent 的记忆机制

##### 1. 长期记忆 vs 短期记忆

​	短期记忆：保存当前任务 / 会话中的临时信息。

​	长期记忆：跨会话保存历史交互，并在未来任务中重复利用。FragFuse 主要利用长期记忆。

##### 2. Memory 的三个核心操作

​	**Memory Retrieval（记忆检索）**：根据当前查询与历史记录的相关性，从 Memory 中检索 Top‑k 相关记录。

​	**Memory‑Augmented Execution（记忆增强执行）**：将检索到的历史记录与当前查询一起提供给 LLM，辅助 Agent 完成任务。

​	**Memory Writing（记忆写入）**：将当前的 “查询 + 执行结果” 写入长期记忆，供后续任务使用。

##### FragFuse 利用的核心漏洞点

​	Memory 会跨时间持久化保存信息，并在后续查询中自动检索和重新提供给 LLM。因此，攻击者可以将敏感片段先存入 Memory，再通过后续查询将其取出并融合。



### 基于记忆的 LLM Agent 攻击

​	已有的记忆攻击主要通过**篡改 Agent 行为或窃取 Memory 信息实现攻击**，而 **Frag Fuse** 则利用 **Agent Memory 的持久化与检索机制，在不改变原始任务意图的情况下绕过访问控制**。

## Frag Fuse攻击流程概览

Frag Fuse 利用 **Agent Memory** 产生的时间通道（Temporal Channel），将一个原本会被访问控制拦截的请求拆分为**两次交互**：

1. **试探性查询**：攻击者通过试探性查询，找出其中容易触发访问控制的敏感片段，并对这些片段进行拆分和掩盖，使当前请求能够绕过访问控制。
2. **嵌入与注入**：将这些敏感片段嵌入一个看起来正常的 Host Query 中，构造 **Carrier Query**，诱导 Agent 将其写入长期 Memory，同时为后续检索做好准备。
3. **检索与重组**：完成 Memory 注入后，攻击者再次发送 **Attack Query**，让 Agent 检索出之前存储的敏感片段，并通过 **Fusion Instruction** 将这些片段重新组合，从而恢复原本被禁止的任务意图，最终绕过访问控制并执行该任务。

### 三阶段攻击设计

针对上述挑战，FragFuse 依次设计了三个阶段，依次衔接，完成整个攻击过程：

| 阶段     | 名称                   | 作用                                                         |
| -------- | ---------------------- | ------------------------------------------------------------ |
| 第一阶段 | **Fragment Discovery** | 发现敏感片段，识别哪些内容容易触发拦截，并确定拆分与掩盖方式。 |
| 第二阶段 | **Memory Injection**   | 将敏感片段通过 Carrier Query 存入 Agent 的长期 Memory。      |
| 第三阶段 | **Query Fusion**       | 检索已存入的片段，并通过 Fusion Instruction 重新融合，恢复完整任务意图。 |

---

### 面临的三个关键挑战

- **挑战一**：前后两次交互都必须绕过访问控制。
- **挑战二**：第一次存入 Memory 的敏感片段必须能够在第二次交互中被可靠检索。
- **挑战三**：检索出的敏感片段必须能够被正确重构，以恢复原本被禁止的任务意图。

### 解决挑战的方法思路

#### Stage 1: Sensitive Fragment Discovery（敏感字段检测）

本阶段主要解决攻击中的第一个挑战，即如何让包含敏感内容的请求绕过访问控制。

Frag Fuse 使用 **LLM-based FRAGEXTRACTOR**，通过迭代式识别与替换，逐步剥离 Query 中可能触发访问控制的敏感片段：

- 从被拦截的原始 Query 中，利用 FRAGEXTRACTOR 识别可能触发访问控制的敏感片段。
- 将识别出的敏感片段替换为预定义的占位符 `< >`，生成 **Masked Query** 并重新提交验证。
- 如果替换后的 Masked Query 仍然被拒绝，则继续识别并掩盖其他敏感片段，重复上述过程，直到整个 Query 能够通过访问控制。

最终，该阶段输出两个关键结果：
1. **敏感片段集合**：所有被识别并替换的敏感内容。
2. **Masked Query**：经过掩盖后能够绕过访问控制的查询模板。

这两个输出为后续的 **Memory Injection** 和 **Query Fusion** 阶段提供了基础。

#### Stage 2: Carrier Construction & Injection（载体构造与注入）

本阶段主要解决攻击中的第二个挑战，即如何将敏感片段注入 Memory 并保证后续能够被可靠检索。

Frag Fuse 通过载体构造与注入，将第一阶段发现的敏感片段嵌入正常查询中，具体流程如下：

- 选择一个能够通过访问控制的正常 **Host Query** 作为载体，确保整体请求在提交时不会被拦截。
- 将第一阶段发现的敏感片段进一步按词拆分，降低单个片段的敏感度，并利用预定义的占位标记进行包装，从而构造出 **Carrier Query**。  <small>Host Query + 被拆散的敏感片段 = Carrier Query</small>
- 该构造方式具备双重效果：
  1. **规避访问控制**：拆分后的片段不再以原始敏感形式出现，降低了触发拦截的风险。
  2. **建立检索线索**：Host Query 的上下文语义为后续 Memory Retrieval 提供了可被自然检索的关联线索。

最后，通过正常交互将 Carrier Query 提交给 Agent，使 Agent 自动将相关内容写入长期 Memory。这一注入过程不触发异常行为，为第三阶段的检索与重组奠定了基础。

#### Stage 3: Fragment Retrieval & Fusion(字段检索与融合)

本阶段主要解决攻击中的第三个挑战，即如何从 Memory 中可靠地检索出已存入的敏感片段，并将其正确重构以恢复原始被禁止的任务意图。

Frag Fuse 通过检索与融合，将第二阶段注入的敏感片段从长期 Memory 中取出并填回被掩盖的位置，具体流程如下：

- 攻击者第二次发送 **Attack Query** 时，再次加入之前使用的正常查询内容（Host Query 中的上下文线索），以帮助 Agent 在 Memory 中精准定位到之前注入的对应记录。
- 通过一个精心构造的 **Fusion Instruction**，指示 Agent 从检索到的 Memory 记录中提取被占位标记包装的敏感片段。
- 将提取出的敏感片段按顺序填入第一阶段生成的 **Masked Query** 中被替换的位置，从而完整恢复原本被禁止请求的完整语义。

该阶段的核心操作链可概括为：

> **Memory Retrieval → Fragment Extraction → Masked Query Filling = Full Original Query**

至此，原本被访问控制拦截的请求被完整复现，攻击者成功实现了任务意图的绕过与执行。
