# Understanding the planning of LLM agents: A survey 阅读记录

原文链接：[Understanding the planning of LLM agents: A survey](http://arxiv.org/abs/2402.02716)

## INTRO

传统的 LLM Agent 规划方法主要依赖**符号规划**和**强化学习**。但这类方法存在明显局限：

- **符号方法**：需要将自然语言问题转换为结构化的符号模型，过程复杂且依赖人工；同时**容错性较差**，少量建模或执行错误都可能导致整个任务失败。
- **强化学习方法**：通常需要通过与环境进行**大量交互和样本训练**才能学到有效策略，数据收集成本高，在真实场景中往往不够实用。

**总结：传统方法要么依赖人工进行复杂的符号建模，要么需要大量昂贵的交互数据，且对错误的容忍度较低。**

随着 LLM 的发展，其在**推理、工具使用、规划和指令遵循**等方面展现出较强的能力，因此可以将 LLM 作为 Agent 的**认知核心（大脑）**，为解决传统规划方法的局限提供新的思路。

现有研究开始利用 LLM 的能力进行 Agent 规划，但已有综述主要关注 LLM、决策、推理、工具学习或自主 Agent 等方向，**缺少对 LLM Agent 规划能力的系统分析**。

因此，本文从 **Agent 的规划能力**出发，对现有方法进行系统梳理，并将其归纳为 **5 个主要方向**，分析各类方法的思想、优势与局限。



## Task Decomposition

**Task Decomposition 本质就是"分治"（divide and conquer）**：把复杂任务拆成多个子任务，再分别进行规划。论文主要分成两种方式，Decomposition-First Methods 和 Interleaved Decomposition Methods。

![image-20261007161626474](./Understanding the planning of LLM agents A survey 阅读记录.assets/image-20261007161626474.png)

### Decomposition-First Methods（先分解）

先把整个任务拆成多个子任务 → 再依次为每个子任务制定计划并执行。

例如：

> “帮我组织一次旅行”
> → ①确定目的地 → ②订酒店 → ③订机票 → ④制定行程

Plan-and-Solve范式就是属于这一种

**优点：**

- 子任务与原始任务联系更紧密；
- 整体规划比较清晰；
- **不容易忘记原始目标，也相对减少任务偏离和幻觉。**

**缺点：**

- 所有子任务一开始就确定了，**灵活性和容错性较差**；
- 如果前面的任务分解出现错误，后面的执行可能全部受到影响；

### Interleaved Decomposition Methods（交错分解）

任务分解和子任务规划**交替**进行，不一次性把所有任务拆完，而是**根据当前状态**逐步**决定下一步**。

例如：

> “帮我组织一次旅行”
> → 先确定目的地
> → 根据目的地再决定订什么酒店
> → 根据酒店位置再规划交通
> → 再决定具体行程……

也就是说是：分解 → 规划/执行 → 获取当前状态 → 再分解 → 再规划……

ReAct范式属于这一种

**优点：**

- 可以根据**环境反馈动态调整**；
- 不需要提前确定整个任务的执行路径；
- **灵活性和容错性更高**。

**缺点：**

- 对于非常复杂、步骤很多的任务，会产生很长的规划轨迹；
- LLM 可能因为上下文越来越长而出现**幻觉、遗忘之前的信息、逐渐偏离原始目标**。

### Contrast

| 方法                    | 核心思想                               | 优点                       | 缺点                                     |
| ----------------------- | -------------------------------------- | -------------------------- | ---------------------------------------- |
| **Decomposition-First** | **先全部分解，再逐个规划执行**         | 整体性强，不容易偏离原目标 | 灵活性差，前面出错可能导致后续失败       |
| **Interleaved**         | **边分解、边规划，根据反馈决定下一步** | 灵活、容错性高             | 长任务容易导致上下文过长、幻觉和目标偏移 |

## Multi-Plan Selection

这种方法针对 **LLM 生成结果具有不确定性**的问题，不只让 LLM 生成一个计划，而是生成多个候选计划，再通过搜索或评价机制从中选择一个较优的计划执行。

主要包含两个阶段：

> **Multi-Plan Generation → Optimal Plan Selection**
> 生成多个候选计划 → 搜索/评价并选择最优计划

### Multi-Plan Generation

让 LLM 不只思考一条路径，而是通过**采样、提示或搜索**生成多个不同的候选计划。

代表方法：

- **Self-Consistency**：通过不同的采样结果生成多条推理路径。
- **Tree-of-Thought (ToT)**：让 LLM 生成多个 Thought，并组织成**树状结构**。

### Optimal Plan Selection

生成候选计划后，需要从中选择一个较优的计划。论文中的方法主要将 **LLM 与经典搜索算法结合**：



- **Self-Consistency**：采用**多数投票**，选择出现次数最多的结果。

- **ToT**：利用 **BFS / DFS** 等树搜索方法寻找较优路径，并让 LLM 对候选 Thought 进行评价。



**核心思想**：**LLM** 负责**产生/评价**候选方案，之后用搜索算法负责在候选空间中进行搜索。



**优点：**

- 相比只生成一个计划，可以**探索更多可能的解决方案**；
- 降低单个计划不合理或不可行带来的风险；
- 对复杂任务具有更强的搜索能力。

**缺点：**

1. **计算成本高**
   要生成和评估多个计划，需要多次调用 LLM，token 和计算量都会增加。
2. **LLM 自身的评价能力有限**
   如果让 LLM 判断哪个计划更好，那么可能出现**“LLM 自己生成方案，再自己错误评价方案”**的问题。
3. **存在随机性**
   LLM 的生成和选择具有随机性，可能导致最终选择结果不稳定。

## External Planner-Aided Planning

LLM 虽然具有较强的推理和任务分解能力，但面对**约束复杂、动作空间严格或需要精确规划**的问题时，仅依靠 LLM 可能生成不可行的计划。因此，这类方法：**LLM**  **+**  **External Planner**，让 LLM 负责理解自然语言、分析环境和提供推理信息，而由专门的 Planner 负责实际的规划搜索。论文根据外部 Planner 的类型，将其分为：Symbolic Planner + Neural Planner。

### Symbolic Planner

**核心思想：**

将 LLM 理解的自然语言任务转换成**形式化的符号表示**，再交给传统符号规划器进行精确搜索。

典型流程：

> **Natural Language → LLM → PDDL/ASP → Symbolic Planner → Plan**

*PDDL/ASP是两种不同的符号描述语言*

**优点：**

- 符号规划具有较强的**稳定性、可解释性和理论完整性**；
- 对具有严格约束的任务更加可靠；
- LLM 可以降低传统符号系统中**人工构建符号模型的成本**。

**缺点：**

- 仍然需要把自然语言转换成形式化表示；
- 如果 LLM 生成的 PDDL/ASP 模型错误，可能导致规划失败；
- 对动态、开放环境的适应能力有限。

###  Neural Planner

使用通过 **RL / imitation learning** 训练好的神经网络*（通常为轻量级的）*作为 Planner，让它快速生成或选择动作。

**特点：**

- **规划效率高**：模型参数量较小，能够快速完成规划和决策；
- **领域内规划能力强**：经过特定领域的数据训练后，可以获得较好的规划能力；
- **泛化能力有限**：面对复杂、少见或训练数据不足的问题时，容易出现性能下降。



因此，将**轻量级 Neural Planner 与 LLM 结合**，利用两者的优势互补：

> **Neural Planner：快速决策、提高规划效率**
> **LLM：复杂推理、较强泛化能力**

代表方法包括 **CALM** 和 **SwiftSage**。

- **CALM**：语言模型首先根据环境信息生成候选动作，再由 **DRRN** 对候选动作进行重新排序，最终选择动作。
- **SwiftSage**：采用“**快思考 + 慢思考**”机制。正常情况下使用经过 imitation learning 训练的 **Decision Transformer** 快速进行规划；当执行过程中出现错误或遇到复杂问题时，再切换到 LLM 进行更复杂的推理和规划。

**优点：**

- 结合 Neural Planner 的**高效率**和 LLM 的**推理、泛化能力**；
- 对简单任务可以快速处理，复杂任务再调用 LLM，能够在**规划能力和效率之间取得平衡**。

**缺点：**

- Neural Planner 的能力依赖训练数据，在**未见过或复杂的任务上泛化能力较弱**，引入 LLM 后虽然能够提升复杂任务的处理能力，但也会增加**推理成本和系统复杂度**。

## Reflection and Refinement

LLM Agent 在规划和执行过程中可能由于**幻觉、推理能力不足或环境反馈有限**而产生错误，甚至陷入重复的“thought loops”。因此，引入 **Reflection and Refinement** 机制，使 Agent 能够根据过去的执行结果和反馈总结错误，并对后续规划进行修正，从而提高**容错和错误纠正能力**。

现有方法的主要区别在于**反馈来源和修正方式不同**：

- **Self-Refine / Reflexion**：主要依靠 LLM 自身进行反馈和反思；
- **CRITIC**：引入搜索引擎、知识库等外部工具验证结果，再进行修正；
- **LEMA**：将错误规划及其纠正结果进一步用于模型微调。



**局限**

Reflection 虽然能够提高容错能力，但目前缺乏**收敛性的理论保证**。Agent 不断进行反思并不意味着一定能够越来越接近正确答案，也可能重复错误或陷入新的思维循环。

## Memory-Augumented Planning

Agent 的**记忆（Memory）**可以保存过去的知识和经验，在当前任务规划时进行利用，从而提升规划能力。

本文将 Memory-Augmented Planning 分为两类：

1. **RAG-based Memory**：记忆**存储**在**模型外部**，需要时**检索**
2. **Embodied Memory**：记忆**融入**模型**参数**，通过**训练**获得

### RAG-based Memory

将 Agent 过去的经验存储在**外部 Memory Storage** 中，在进行新任务规划时，根据当前任务检索相关的历史经验，并将其提供给 LLM。



**优点：**

- 不需要修改模型参数；
- 记忆可以动态更新、增加和删除；
- 可以存储大量历史经验。

**缺点：**

- 依赖额外的存储和检索机制；
- 检索质量会影响规划效果；
- 错误或无关的记忆可能干扰当前规划。

### Embodied Memory

通过 **Fine-tuning** 将 Agent 的历史经验直接融入 LLM 的模型参数，使模型能够在后续任务中直接利用这些经验。

<small>*微调（Fine-tuning）：拿一个已经预训练好的大模型，在小规模的特定任务数据集上继续训练，轻微修改模型权重，让模型适配你这个特定任务。*</small>



**优点：**

- 经验直接融入模型，不需要每次额外检索；
- 能够学习历史经验中的规划模式；
- 推理过程相对简单。

**缺点：**

- 更新记忆需要重新训练；
- 参数化记忆难以直接修改和删除；
- 训练成本较高，错误经验也可能被模型学习。
